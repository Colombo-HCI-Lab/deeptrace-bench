# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this repo is

The benchmark harness for the Colombo HCI Lab's South Asia deepfake detection project: open video and audio detectors run on South Asian deepfake datasets under one evaluation setup, with results reported per group. It starts with existing datasets and models (reproduce published numbers, zero-shot runs, fine-tuned baselines) and later evaluates the data collected through the sibling repo `deeptrace`. The site's How it works and Getting started pages have the workflow. `docs/` is the public site (https://colombo-hci-lab.github.io/deeptrace-bench/, Astro): five guided pages (the Timeline, which is the home page, Results, How it works, Coverage, Compute cost) plus every doc under `/docs/`, written in `docs/src/content/docs/` (how it works, getting started, results, evaluation, models, datasets, data policy, where to run and the rest).

Scaffolded 2026-10-03; runs end to end since 2026-10-04. As of 2026-10-05 every configured model has an adapter except AltFreezing (weights unreachable): GenD (CLIP and PE backbones), SBI, LipForensics (FAN landmarks, upstream's mouth crops), nine DeepfakeBench detectors and Effort through one adapter (Effort's weights wait on Google Drive's quota), AASIST, AASIST-L, AASIST3, the XLS-R family (AASIST, SLS and Mamba back ends, run without fairseq or mamba-ssm through `models/_fairseq.py` and `models/_mamba.py`), AntiDeepfake MMS-300M and wav2vec 2.0 small, DF Arena 500M and 1B, and the audio-visual HAVIC. Seventeen pass parity (`scripts/parity.py`, `results/parity/`); the rest, GenD among them, pass strict loads and the pipeline check only. The first zero-shot round ran on 2026-10-12: 48 model and evalset pairs scored in all, findings in `docs/src/content/docs/results.md`, the round-by-round record in `progress.md` beside it. The first full benchmark round (2026-10-27 to 28) ran through deeptrace-experiments' `matrix` stage on SPARK and two 24 GB GPUs outside it; `exp.py import` writes each wave's runs into `results/<run_id>/` and one row per pair into `results/ledger.csv` (metrics, compute, energy). Builders are written for every open or click-through dataset, including parquet-row datasets (IndicSynth, IndicTTS challenge), zips inside zips (BD-GRF6) and tar-only IndicSUPERB. Still stubs: the request-only and gated builders whose files nobody has seen (FakeAVCeleb, DeePhy, DF-Platter, InDeepFake, IndieFake, Deepfake-Eval-2024, Casual Conversations v2, SEA-Spoof, Svarah), native preprocessing, the shortcut probe.

## Commands

```bash
uv sync                                    # Python 3.12, torch 2.8 (cu128 on Linux)
uv run pytest                              # synthetic fixtures only
uv run ruff check . && uv run ruff format .
uv run scripts/setup_models.py --list | <ids> [--record] | --wave N
uv run scripts/setup_datasets.py --list | <ids> [--languages ..] | <id> --from PATH | --manifest
uv run scripts/setup_datasets.py <ids> --sample N [--seed S] --manifest   # smoke namespace
uv run scripts/score.py --model <id> --evalset <id> [--shard i/n] [--smoke] [--save-crops K]
uv run scripts/evaluate.py --model <id> --evalset <id> [--publish] [--smoke]
uv run scripts/smoke.py [--model gend] [--sample 2] [--device auto|cpu|mps|cuda] [--keep]
uv run scripts/parity.py export --model <id> --evalset <id> --smoke   # then the reference and compare it prints
uv run scripts/profile_models.py --device cuda   # params, FLOPs, GPU time per model -> results/profile/
uv run scripts/build_site.py [--citations] # rewrite the site's data (status.json, catalog.md) from the store
uv run scripts/archive.py --to <archive> [--from <store>]   # copy per-item results and run records off the store
cd docs && npm ci && npm run dev           # the site locally; npm run build fails on a broken doc link
```

GPU runs on the DESI lab's SPARK cluster go through a separate private repo, [UNIL-DESI/deeptrace-experiments](https://github.com/UNIL-DESI/deeptrace-experiments) (cloned at `~/workspace/UNIL-DESI/deeptrace-experiments/`, its own `CLAUDE.md`), because Cluster-CI only runs repos in that org. It pins a commit of this repo in `params.yaml` and runs these scripts as DVC stages in this repo's own locked venv, so code changes land here first and then the pin moves. Its `scripts/exp.py` places, watches and reads runs; `spark.md` walks through it, so change the two together. Since 2026-10-16 the tests and smoke test pass there on the x86 worker (an RTX 3090), and a scoring run (AASIST on Urdu CSALT) reproduced the 2026-10-12 numbers within 2e-4. `docs/src/content/docs/spark.md` is the team's how-to for running there.

Paths come from `DTB_ROOT` and `DTB_CACHE` (`.env`, see `.env.example`); `docs/src/content/docs/store_layout.md` maps the tree. `DTB_NAMESPACE=smoke` (set by `--smoke`, `--sample` and `smoke.py`, never in `.env`) moves everything item-level under `DTB_ROOT/smoke/`.

## Rules

- **No data in git.** Datasets, weights, manifests, per-item scores, split assignments and per-subject tables live under `DTB_ROOT`. Only code, configs, docs and aggregate tables are committed. `scripts/hooks/pre-commit` enforces it; keep it working. Test fixtures are synthetic. After each round, `scripts/archive.py` copies every store's per-item results into the private archive in phase 2's Google Drive folder, `benchmark results/` (`store_layout.md#archive`); nothing item-level goes anywhere else.
- **One environment.** No dlib, fairseq or mamba-ssm. Upstream code is cloned at a pinned commit into `third_party/` (git-ignored) and loaded by adapters; never copy code from Effort (no licence), SBI (research only) or DeepfakeBench (CC BY-NC) into the repo. Compatibility fixes go in `patches/<repo>/`.
- **Parity before results.** An adapter counts only after its scores match the upstream code in its original environment on about 200 items (within about 1e-3) and its score direction checks out on the reproduction evalset. See `docs/src/content/docs/models.md`.
- **Evalsets, not datasets.** Score only through `configs/evalsets/`. Cross-corpus evalsets never feed headline numbers.
- **The contamination guard is only as good as `training_data`.** List every dataset a model's released weights saw, including pretraining, and give each dataset its `derived_from`. Don't bypass the guard with `--force` for anything reported.
- **One evaluation setup.** `configs/eval/default.yaml` is the only place settings live; it is `proposed` until the team settles decision 5.
- **Weight hashes** are pinned in `configs/weights.lock.yaml` via `--record` on first fetch, never edited by hand.
- **Failures are data.** Preprocessing failures get a status and are counted per group, never dropped.
- **Pipeline tests are never results.** Datasets and evalsets with `role: pipeline_test` only prove the code works; the registry keeps them out of real evalsets and `--publish` refuses them and anything in the smoke namespace. Run `scripts/smoke.py` after any change to the pipeline.
- **Builders are samplable.** A dataset builder defines `build_manifest` and a way to label items before download: `label_from_path`, or `METADATA_FILES` with `labels_from_metadata` where labels live in a file, or `ROW_COLUMNS` with `label_from_row` for audio embedded in parquet rows (`datasets/_parquet.py`). It works on a partial tree; test fixtures use invented file names.
- **Conversions never overwrite downloads.** A weight whose Hub file is called `model.safetensors` gets its own local `name`, since the converted file has that name; `save_converted` refuses the clash.
- **Upstream code is imported, never copied.** Through `models/_upstream.py`; code inside a Hugging Face repo is pinned as `upstream.host: hf` and never loaded with `trust_remote_code`. Downloads are converted once to `model.safetensors` and loaded with every key matching.

## Conventions

- `uv` for everything. Logging, not print, in library code; scripts print only tables. Docstrings on public functions; comments say why.
- Config ids match file names. Dataset and model facts in configs and docs carry the date they were checked.
- Commit titles start lower case, no prefix, one short line.
- Docs are read by the whole team: no personal machines, no people outside the team's working group.
- **Docs are site pages.** Each is a Markdown file in `docs/src/content/docs/` with `title` and `description` in its front matter, and no H1 (the layout prints the title). Link another doc as `name.md#section` and a repo file as `/path/from/repo/root`; both also work on GitHub, and the build fails on a broken one. `docs/src/reference/status.json` and `catalog.md` are written by `build_site.py`, never by hand; the descriptions behind them live in `docs/src/reference/catalog.yaml`. `build_site.py` rebuilds the runs from the store it can see, so run it where every run's results are: the Mac's store lacks the audio rounds' results (as of 2026-10-26), and a rebuild there drops them from the site. It also drops any run whose model or evalset config changed after it ran, except where the change can't affect what the run measured: an evalset field added later and left unset (`subset`), or a model's descriptive fields (`name`, `status`, `wave`, `licence`, `paper`, `notes`), which `status.py` checks against the config's git history. A push to `main` touching `docs/` redeploys the site (`.github/workflows/pages.yml`). The design is "Sienna" (chosen 2026-10-25 from the Claude Design project "deeptrace bench docs", replacing "Plate"): Instrument Sans for prose and headings, Geist Mono for data, labels and code, on warm paper (`#fdfcfa`, ink `#171412`); hairline rules only, no shadows or rounded corners; light only; sienna (`--accent`) marks the current page, kickers and links, and one stepped diverging AUC scale (`--good` petrol, `--bad` sienna) colours scores. Tokens and shared styles are in `docs/src/styles/site.css`, and `PAPER`, `TINT`, `GOOD` and `BAD` in `docs/src/lib/guide.ts` must match it. No serif faces. Layout follows the content column's width through container queries on `main`, not the window's. The shell is wide (`--shell`, 1760px) so tables use the screen; prose keeps its 72ch measure. The Timeline, Results and How it works pages are built from `progress.md`, `results.md` and `method.md` by heading (`docs/src/lib/guide.ts`), so keep their H2 and H3 titles, the `- **Label.** body` form of their lists and the tables of `method.md` and `results.md`'s Experiments; those three docs have no page of their own: links to them land on the guided pages, and a section with no layout of its own (a round's write-up in `results.md`, say) shows there as prose, so nothing in the doc goes unshown. **Every page has one address** (since 2026-10-29): every other doc is a page at the site root (`/<slug>/`), and `/docs/` holds only the Every doc index plus forwarding stubs for the docs' old `/docs/<slug>/` addresses. Never add a second rendering of a page. The build fails on a link to a missing page, to a forwarding stub, or to an anchor the target lacks, so link where a page lives now. The Results page's two grids (speech, faces) take their rows and columns from `status.json`'s runs (a quick subset gives way to its full set), each row's facts from `results.md`'s detectors table and its group from `SPEECH` and `FACES` in `guide.ts`: give a new detector a row there and a group, or it lands in Other with facts from the catalog. Navigation is one nav on every page, declared in `docs/src/lib/nav.ts` (groups, order, labels, the previous and next links): a rail on wide screens, the site bar's Menu on narrow ones. Docs in its Models and datasets group list their H2s in the rail, always open; every other page shows its sections in a bar above the text. The two catalogs are built from `status.json` (`docs/src/lib/catalog.ts`, `docs/src/pages/model-catalog/`, `docs/src/pages/dataset-catalog/`): an index page each, with counts, one summary table and small plots, and a page per model and per dataset, so no page runs long; prefer tables and plots to prose there. Kinds of fake (face swap, lip-sync, text to speech and the rest) are defined once in `catalog.yaml`'s `fake_types` and tagged per entry (`fakes` on a dataset, `catches` and `cue` on a model); the dataset index's Kinds of fake table shows which kinds no dataset or model covers. `catalog.md` stays generated for reading on GitHub, and its old site URLs and `#model-<id>` and `#dataset-<id>` anchors forward to the new pages. `datasets.md` is the Access and requests page. Figures sit between a doc's blocks after a named heading (`FIGS` in `docs/src/lib/figures.ts`, components in `docs/src/components/figures/`); when a doc's facts change, check the figure that draws them. Docs merged into others are listed in `MOVED` in `docs/src/lib/links.mjs`, which keeps their old URLs working; link the new doc instead.
- **One home per fact.** A hand-written doc states each fact once and every other page links to it; generated pages (the catalogs, Coverage, Compute cost) may repeat. Homes: `method.md` (pipeline, key terms, repo layout), `getting_started.md` (install, smoke test), `progress.md` (status, plan, open decisions), `results.md` (experiments, numbers, findings), `evaluation.md` (settings, metrics, verdicts), `models.md` (trust status, parity, porting notes), `datasets.md` (access), `data_policy.md` (git rules, licence clauses), `store_layout.md` (`DTB_ROOT`, run ids, the archive), `spark.md` (every machine). Use tables for anything enumerable, and no preamble that restates the front matter's description.
- **After each round of runs**, add a dated entry at the top of the timeline in `progress.md` (what ran, commit range), update its "Where things stand" and "Next", and refresh `results.md` (its Experiments table, numbers and Insights) if new numbers or experiments came in. Numbers there are dated snapshots copied from the store's aggregates.
