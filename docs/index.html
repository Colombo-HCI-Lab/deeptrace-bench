deeptrace-bench

Can today's deepfake detectors catch fakes in South Asian languages and faces? Most were trained on English speech and Western faces. This benchmark runs published, open detectors on South Asian audio and video under the same rules, and reports how well each one holds up.

How to read this page

Every number here answers one question: given a clip, can the model tell whether it is real or fake? These are the terms the rest of the page uses.

Deepfake
Audio or video made or changed by AI to look or sound like a real person: a cloned voice, a swapped face, speech generated from text.
Detector (model)
A neural network that listens to a clip, or looks at the faces in it, and gives a score from 0 (real) to 1 (fake). Every detector here comes from a published paper with released weights.
Dataset and evalset
A dataset is a published collection of real and fake clips. An evalset is the exact slice we score: which dataset, which languages, which clips count as real and which as fake. One dataset can feed several evalsets.
AUC
The chance that the model gives a randomly picked fake clip a higher score than a randomly picked real one. Higher is better.
0 · always wrong0.5 · coin flip1 · perfect
EER (equal error rate)
Pick the cut-off where the share of real clips wrongly called fake equals the share of fakes wrongly called real. That shared error rate is the EER. Lower is better; 50% is guessing.
Zero-shot
Testing a model on data unlike what it learned from, without retraining it. Most results here are zero-shot, which is the point: they show how detectors trained elsewhere do on South Asian data.
Reproduction
Running a model on the dataset its own paper used, to check our numbers match the published ones. If they do, we can trust our setup on new data.
Same corpus or cross corpus
Same corpus: real and fake clips come from the same recordings, so the only difference is the fakery. Cross corpus: they come from different sources, so a model can score well by noticing the microphone rather than the fake. Cross-corpus numbers never count as headline results.
Parity check
Before we trust our copy of a model, we run it and the authors' original code on the same ~200 clips. The scores must agree to within 0.001.
Contamination guard
A model can't be tested fairly on data it saw while training. The harness compares each model's training data with every evalset and refuses those pairs (marked ⊘).
How a score is made

Pipeline

Five steps turn a published model and a dataset into one row of results. Three checks sit along the way so that a number only counts when it can be trusted.

1 · configs/

Configure

One file per model (where its code and weights come from, what it trained on), per dataset (where to get it, its licence) and per evalset (what gets scored). One shared set of evaluation rules.

2 · setup_*.py

Set up

Download each model at a fixed version and check its weights. Download each dataset and list every clip with its label (real or fake), language and generator.

3 · score.py

Score

Prepare each clip the same way for every model (audio cut into 4 s windows; faces found and cropped in video), run the model, store one fake-score per clip. Can stop and resume.

4 · evaluate.py

Evaluate

AUC and EER with 95% confidence intervals, overall and per group (language, generator). Clips that fail, such as a video with no face, are counted, never dropped.

5 · --publish

Publish

Only summary tables go into the public repo. Every row carries how its real and fake clips were paired and the contamination check's verdict.

The detectors

Models

Every model comes from a published paper with released weights. Parameters are the numbers a model learned in training; a bigger model needs more computing power but isn't always more accurate. Citation counts are a rough signal of how influential a paper is, and newer papers have had less time to collect them. Each name links to a fuller description in the models and datasets reference.

Where the test clips come from

Datasets

South Asian sets are what the benchmark is for. Reproduction sets check our numbers against published ones. Real-reference sets supply genuine speech when a dataset only contains fakes. Access says what it takes to get the data. The reference lists the labels each dataset ships, such as speaker, gender, age or race, and which of them our builds record.

Every countable run

Results

One row per model and evalset that has been scored in full. Wall time is how long the whole run took, including reading the audio from shared storage.

  • The evaluation rules are proposed until the team settles them (decision 5), so these numbers can still move.
  • Below chance (AUC under 0.5) on a reproduction set means a bug in how scores are read; on a South Asian set it is a real finding about the model.
  • Source overlap: the model's pretraining used a corpus that the evalset also draws on. Reported with a warning, kept out of headline numbers.
  • Cross-corpus evalsets take real and fake clips from different sources and never enter headline numbers.
What it costs to run

Compute

Measured with each model already loaded, counting only the model's own work. Audio models read 4-second windows, so a longer clip costs more. Video models read one face crop per frame, 32 frames per video for most of them.

Estimated time for a full evalset

Model time only, from the measured time per window, for every evalset whose size is known. Where a real run exists, its wall time follows in grey: real runs take longer because reading thousands of files from shared storage, not the model, is usually the slow part.
