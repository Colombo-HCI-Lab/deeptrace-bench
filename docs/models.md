Each modality pairs classic detectors with foundation-model ones (GenD on two backbones for video; the XLS-R family, AntiDeepfake and DF Arena for audio). The DeepfakeBench detectors add different cues on the classic side: plain texture (Xception, EfficientNet-B4), forgery features separated from content (UCF), frequency (F3Net), phase (SPSL), reconstruction (RECCE), noise residuals (SRM), consistent representations (CORE) and manipulation attention (FFD). LipForensics reads mouth movement and HAVIC audio and video together, the two aimed at lip-sync fakes, v1's focus. On the audio side the multilingual pretraining varies on purpose: AntiDeepfake's MMS-300M and wav2vec 2.0 small share their post-training data, and the XLS-R models share ASVspoof 2019 LA training with different back ends (AASIST, SLS, Mamba). If both kinds fail on the same attribute, the cause is likely in the data rather than one model.

## One environment, ported adapters

Everything runs in this repo's single environment (Python 3.12, torch 2.8, transformers 4.56). Upstream repos pin much older stacks (DeepfakeBench: Python 3.7 and torch 1.12; XLS-R + AASIST: torch 1.8 and fairseq) that don't run on H100s, so we don't use them for results. Instead:

1. `setup_models.py` clones the upstream repo at its pinned commit into `third_party/` and archives it to `DTB_ROOT/upstream/`. Code from Effort (no licence), SBI (research only), DeepfakeBench (CC BY-NC) and XLS-R + SLS (no licence) is never copied into this repo; MIT code (AASIST, GenD, HAVIC, LipForensics, XLSR-Mamba) may be.
2. The adapter (`src/deeptrace_bench/models/<module>.py`) loads the one model file it needs from the checkout with `importlib`. Small compatibility fixes go in `patches/<repo>/` (see `patches/README.md`). Libraries the one environment can't have are stood in for while upstream code imports: fairseq by transformers' wav2vec 2.0 (`models/_fairseq.py`) and mamba-ssm's CUDA kernels by pure PyTorch (`models/_mamba.py`).
3. `convert_checkpoint` turns the download into `model.safetensors` with normalised keys, once. Adapters then never unpickle Google Drive files.
4. **Parity check** before any result counts: run the upstream code in its original environment (an Apptainer image or a throwaway old-torch venv, on CPU or an A100) on about 200 items, run the adapter on the same items, and require scores to agree within about 1e-3. `scripts/parity.py` does this with a reference script per upstream (see [adding_a_model.md](adding_a_model.md)) and writes `results/parity/<id>.json`. This is what licenses every patch.
5. **Score direction**: on the reproduction evalset (FF++ test, ASVspoof 2019 LA eval), AUC must come out above 0.5. An inverted logit otherwise flips every result silently.

Expect these breakages on Python 3.12 and torch 2.x: `torch.load` now defaults to `weights_only=True`; `np.float` and `np.int` are gone; `distutils` and `imp` are gone.

## Per model

**DeepfakeBench: Xception, EfficientNet-B4, UCF, F3Net, SPSL, RECCE, SRM, CORE, FFD.** Commit `f188b1c` and release v1.0.1 weights, which ship 13 frame-level checkpoints (also Capsule, CNN-Aug, MesoNet and MesoInception, which the same adapter could load; no release ships LSDA, CLIP, SBI or Effort weights). **Adapter written 2026-10-05** (`models/deepfakebench.py`, one class, `input.detector` picks the yaml): it imports the one detector file and its backbone from the checkout with stand-ins for DeepfakeBench's training losses, metrics and tensorboard, builds the network with upstream's own class and yaml, and loads the converted checkpoint with every key matching. All five load strictly; the EfficientNet-B4 mismatch reported in #79 doesn't occur with `efficientnet-pytorch` 0.7.1. Input as DeepfakeBench's test transform: RGB 256 px crops, cubic resize, mean and std 0.5 (not ImageNet's, as the configs said before); label 1 is fake for all five. UCF scores with its common-forgery head; its inference path also runs the unused content encoder. Known issues: published weights don't reproduce the README table for some users (#109, #159). Issue #151 asks whether every checkpoint is FF++ c23, unanswered, and the detector yamls name single FF++ manipulations for F3Net (NeuralTextures) and SPSL (FaceSwap), which may not describe the released checkpoints; the guard treats all five as trained on FF++ train either way. **Score direction isn't checked yet** for any of the five: it needs FF++ test or Celeb-DF v2, both on request. Parity fixes P(fake) at upstream's label 1, which is what the direction check would confirm. RECCE, SRM, CORE and FFD were added on 2026-10-05 through the same adapter: RECCE builds its encoder with timm's `xception(pretrained=True)`, switched to `pretrained=False` while it is built since the checkpoint replaces every weight, and FFD reads ten template images through `imageio` in its constructor that only its other map types use, so blank 19 x 19 templates stand in. All nine load strictly and pass parity.

**SBI.** `FFc23.tar` (used) and `FFraw.tar` from Google Drive, 141 MB each, `torch.save` dicts whose `"model"` entry is the state dict. **Adapter written 2026-10-05** (`models/sbi.py`): upstream's own `Detector` from `src/inference/model.py`, built with `EfficientNet.from_pretrained` pointed at `from_name` so no ImageNet download happens (the checkpoint replaces every weight). Input as `inference_video.py`: the face box widened by an eighth of its width and height a side and stretched to 380 x 380 (the `box` crop mode, with SBI's own rounding), RGB / 255 with no mean or std; P(fake) is softmax index 1. Upstream keeps every face at least half the largest one's area and takes the max per frame; the shared pipeline keeps the largest face, the same on single-face videos. Boxes come from SCRFD where upstream uses RetinaFace, so parity compares the network on identical crops. Research-only licence: the code stays in `third_party/`.

**GenD.** `yermandy/GenD_CLIP_L_14` on Hugging Face, pinned to revision `891ce01`. Already modern. Trained on FF++ only: the paper's 14 benchmarks, FakeAVCeleb among them, are test sets. **Adapter written 2026-10-04** (`models/gend.py`): it loads upstream's `src/hf/modeling_gend.py` from the pinned checkout and points it at a pinned local copy of its CLIP backbone (`openai/clip-vit-large-patch14` at `32bd642`), which upstream would otherwise fetch unpinned; all ten weight files are hash-pinned. Index 1 of the logits is fake; a video scores the mean of its frames' P(fake). Its face crops come from the shared pipeline, which ports `detector.py`'s SCRFD detector and five-point alignment (see [evaluation.md](evaluation.md)). The detector model, `det_10g.onnx`, is taken from insightface's official v0.7 `buffalo_l` pack (licensed for non-commercial research only) and hashes identical to the third-party mirror upstream downloads. Runs end to end in the smoke test on a laptop (MPS and CPU agree to 2e-6). **Parity with upstream is not checked yet.**

**AASIST, AASIST-L.** Weights committed in the upstream repo; `models/AASIST.py` needs no patch (only `main.py` imports `torchcontrib`). **Adapter written 2026-10-05** (`models/aasist.py`). Upstream labels bona fide 1 and scores the bona fide logit, so P(fake) is the softmax at index 0. Reproduced 2026-10-05 on the full ASVspoof 2019 LA eval set (on a GPU with cuDNN's TF32 convolutions, before `compute.tf32` turned them off; they move single scores by up to 2.5e-2 but left DF Arena 500M's In-the-Wild EER unchanged) (7,355 bona fide, 63,882 spoofed): AASIST AUC 0.999 and EER 1.58% (95% interval 1.41 to 1.75%, paper 0.83%), AASIST-L AUC 0.999 and EER 1.49% (1.32 to 1.66%, paper 0.99%). The direction is settled, and the inverted outputs reported in #17 come from reading the bona fide logit as a fake score. A18 is the hardest attack for AASIST (11% of its clips missed at the EER threshold, against under 3% for every other). The EERs aren't strictly like for like: upstream's evaluation scores only each utterance's first four seconds where ours averages every window, and ours refuses the 1,059 eval clips shorter than a second (see DF Arena below). Zero-shot on In-the-Wild both sit near chance: AASIST EER 44.0% (AUC 0.578), AASIST-L 44.9% (AUC 0.583).

**The XLS-R family: XLS-R + AASIST, XLS-R + SLS, XLSR-Mamba.** All three fine-tune fairseq's XLS-R 300M inside Tak et al.'s `SSLModel` wrapper and were trained on ASVspoof 2019 LA alone, which makes them clean zero-shot probes on every South Asian set. **Adapters written 2026-10-05** (`models/ssl_xlsr.py`, one class, and `models/xlsr_mamba.py`), without fairseq: each upstream `model.py` is imported with stand-in `fairseq` modules (`models/_fairseq.py`) that hand `SSLModel` transformers' `Wav2Vec2Model`, built from the pinned `facebook/wav2vec2-xls-r-300m` config and answering fairseq's `features_only` call, including the per-layer outputs SLS pools over. `convert_checkpoint` renames fairseq's keys (conv layers, positional convolution, attention, feed-forward and norms; the quantiser and other pretraining-only parts are dropped) and every converted key then loads strictly. XLS-R + AASIST: `LA_model.pth` from the authors' Drive folder, byte-identical to the MIT mirror `SpeechAntiSpoofingBenchmarks/W2V2-AASIST`. XLS-R + SLS (ACM MM 2024): `MMpaper_model.pth` from the authors' Drive, saved from `DataParallel` (`module.` prefix stripped); the repo declares no licence, so its code is imported only. XLSR-Mamba: `AustinXiao/XLSR-Mamba-LA` safetensors; mamba-ssm's CUDA kernels are replaced by pure-PyTorch stand-ins with the same names (`models/_mamba.py`: the selective scan step by step, the block, RMSNorm and the fused add-norm functions), checked against transformers' own Mamba mixer, so upstream's `MixerModel` runs unchanged, including its fused ending that normalises the back end's input plus each direction's residual stream. All three use 64,600-sample windows and read P(fake) at index 0 (upstream scores the bona fide logit). As a sanity check, not a result, each scores bona fide ASVspoof 2019 LA eval clips near 0 and spoofed ones near 1. Parity needs fairseq (and mamba-ssm on a GPU) in an old environment and isn't run yet.

**DF Arena 500M and 1B.** `Speech-Arena-2025/DF_Arena_*_V_1` on Hugging Face, code and weights in one repo, non-commercial licence; the top open models on the Speech DF Arena leaderboard (5.9% average EER for 1B). An XLS-R (300M for the 500M model, 1B for the 1B) with attention pooling over every hidden layer and a conformer head. **Adapter written 2026-10-05** (`models/df_arena.py`): the code is pinned like any upstream (`host: hf`) and loaded as a package from the checkout, never with `trust_remote_code`; the XLS-R config that `backbone.py` fetches unpinned comes from a pinned snapshot instead, so loading works offline. Windows go through one at a time (upstream's `forward` unsqueezes a 1-D waveform); P(fake) is the `spoof` softmax. Trained on ASVspoof 2019 (partitions not named, so the guard refuses ASVspoof 2019 LA eval) and 2024, MLAAD (refused on `mlaad_*`), Codecfake, LibriSeVoc, DFADD, CtrSVDD, SpoofCeleb and EnvSDD; In-the-Wild is its reproduction set. Reproduced 2026-10-05: 500M EER 1.51% (95% interval 1.35 to 1.66%) and AUC 0.999 on the full set, against the card's 1.76%; 1B EER 0.67% (0.58 to 0.77%) and AUC 0.999 on the full set, against 0.91% (TF32, as for AASIST above). The protocols differ in two ways that decision 5 should settle for reproduction evalsets: upstream scores only a clip's first four seconds (AASIST's evaluation loader does the same) where our setup averages every window, and our setup refuses the 865 In-the-Wild clips shorter than a second (`min_seconds`) where the card's pipeline tiles them. Parity compares window by window, so it can't see either; the reproduced EERs above include both. On a four-clip Urdu smoke sample it scored both real clips as fake (0.9996 and 0.75): noise at that size, but the kind of gap this benchmark measures.

**Effort.** DeepfakeBench carries Effort's detector (`training/detectors/effort_detector.py`), so it runs through the DeepfakeBench adapter (**written 2026-10-05**): `loralib` (imported, never used) is stubbed, and its hard-coded `CLIPModel.from_pretrained` path is replaced by a CLIP built from the pinned `openai/clip-vit-large-patch14` config; the checkpoint supplies every weight, including the SVD split of all 96 attention projections, and the network builds offline. The FF++ checkpoint `effort_clip_L14_trainOn_FaceForensic.pth` is in Effort's Google Drive folder (`19kQwGDjF18uk78EnnypxxOLaG4Aa4v1h`), which refused every file with "Quota exceeded" on 2026-10-05; retry `setup_models.py effort` later. Known issues: a reported reproduction gap (CDF-v2 AUC 0.885 against 0.956, #19) and keys reported missing from the checkpoint (#18), which the strict load will settle. No licence file (#3).

**HAVIC.** The only open audio-visual detector, `JielunPeng/HAVIC` (`best_ft_model.pth`, 859 MB, MIT). **Adapter written 2026-10-05** (`models/havic.py`), with two compatibility patches (`patches/HAVIC/`): timm 1.x's `Attention` no longer takes `qk_scale` (always None here, so the scale is unchanged), and `HAVIC_FT.forward` passes `use_mask=False` to encoders that don't accept it, which breaks upstream's own inference at this commit (masking is already off). Inputs from the audio-visual loader (`preprocess/av.py`): frames at 5 per second from the start, at most 50; each frame's raw face box resized to 224 and scaled to [0, 1]; windows of 16 frames, stride 2; the audio under them cut with upstream's arithmetic and turned into 128-bin Kaldi filterbanks (torchaudio) stretched to 1,024 frames. Output: a logit per window, P(fake) its sigmoid. Fine-tuned on a random 70% of FakeAVCeleb with no published item list, so the guard refuses it on FakeAVCeleb. It needs videos of at least 3.2 s with a face in 16 sampled frames, so HiDF's 3 s clips are too short; MAVOS-DD Hindi is its South Asian set once its terms are accepted. Upstream's boxes come from FaceX-Zoo's RetinaFace and a frame without a face skips the whole video there, where here it drops out.

**LipForensics.** `lipforensics_ff.pth` from Google Drive (144 MB, `{"model": state_dict}`), MIT. **Adapter written 2026-10-05** (`models/lipforensics.py` and `preprocess/mouths.py`): upstream's `Lipreading` (ResNet-18 with a 3D stem, multi-scale TCN) built from the checkout's config with one output. Mouth crops follow upstream's own preprocessing, its `warp_img`, `apply_transform` and `cut_patch` imported from the checkout: consecutive frames (the first 100), 68 landmarks per frame from FAN (2DFAN4, the `face-alignment` package's TorchScript weights, pinned) on the shared detector's boxes, cropped and decoded with the package's own functions as its `get_landmarks_from_image` does for a given box; landmarks smoothed over 12 frames, each frame warped to the LRW mean face on five stable points, a 96 x 96 mouth patch, grayscale. Then non-overlapping 25-frame clips, centre-cropped to 88 and normalised (0.421, 0.165); P(fake) is a clip's sigmoid. Upstream suggests RetinaFace boxes for FAN. Users report its FF++ numbers don't reproduce (#9). `face-alignment` asks for `opencv-python`, which `pyproject.toml` overrides away so the headless OpenCV 4 build stays the only `cv2`.

**AltFreezing (blocked).** Weights only on RecDrive and Baidu (password `altf`); rechecked 2026-10-05, the RecDrive share page still answers but issues #7 and #8 report the file gone, with no maintainer reply, and no Hugging Face or release mirror exists. DeepfakeBench carries `altfreezing_detector.py` but not its weights. Someone with a working session has to fetch them first.

**AASIST3.** `lab260/AASIST3` (safetensors, transformers-native, KAN layers in the repo). **Adapter written 2026-10-05** (`models/aasist3.py`), no longer dropped but kept as a weak multilingual baseline, not a strong one: the repo says the released weights aren't the paper's, and the Speech DF Arena measures them at 28 to 32% EER on In-the-Wild and ASVspoof 2021. Its front end's config (`facebook/wav2vec2-large-xlsr-53`) is pinned instead of fetched; input pre-emphasised (0.97) per window. The README's example reads index 0 as bona fide, but the training and validation code score index 1 as bona fide; a sanity check on ASVspoof 2019 LA eval (bona fide low, spoofed high) confirms the code, so P(fake) is index 0. Trained on MLAAD, so refused on `mlaad_*`.

**AntiDeepfake MMS-300M and wav2vec 2.0 small.** NII Yamagishi Lab (`nii-yamagishilab/*-anti-deepfake`, checkpoints CC BY-NC-SA 4.0, code BSD-3): speech SSL models post-trained on 74k hours of real and fake speech from 29 corpora in over 100 languages. MMS-300M is pretrained on about 1,400 languages; the small one is wav2vec 2.0 base (English LibriSpeech), so the pair separates the effect of multilingual pretraining under the same post-training. **Adapters written 2026-10-05** (`models/antideepfake.py`): upstream's `models/W2V.py` imported with the fairseq stand-ins, its front end built from `W2V_configs.py`'s fairseq settings translated to a transformers config (`_fairseq.hf_config_from_fairseq`). Each window is normalised to zero mean and unit variance, as upstream's loader does to a whole utterance; P(fake) is index 0. The post-training data includes FLEURS (Hindi, Bengali, Urdu, Tamil, Nepali and more, not Sinhala), MLAAD, all of ASVspoof 2019 LA, LJSpeech, LibriTTS, VoxCeleb2 and SpoofCeleb, all listed for the guard; In-the-Wild is a test set on the cards (EER 2.90% for MMS-300M, 4.24% for the small one). The Hub files are called `model.safetensors`, which is also the name of the converted file, so they are saved under their own names; `save_converted` now refuses a source called `model.safetensors` outright.

**GenD (Perception Encoder L/14).** GenD's second released backbone (`yermandy/GenD_PE_L`), the same adapter and the same FF++-only training as the CLIP one; timm builds `vit_pe_core_large_patch14_336` from its built-in config with `pretrained` forced off (the checkpoint supplies every weight). On Apple's MPS backend one video tripped a Metal assertion; CPU and CUDA run it. The DINOv3 variant (`yermandy/GenD_DINOv3_L`) builds its backbone from Meta's gated `facebook/dinov3-vitl16-pretrain-lvd1689m`, so it waits for someone to accept Meta's terms.

**Candidates, not yet configured** (checked 2026-10-05). Nes2Net-X (`SpeechAntiSpoofingBenchmarks/Nes2Net`, another back end on the same fine-tuned XLS-R, so the fairseq stand-ins should serve it; repo licence undeclared). Forensics Adapter (CVPR 2025, CLIP ViT-L with adapters, weights on Google Drive, CC BY-NC 4.0; no inference script, only `test.py`). LipFD (NeurIPS 2024, the lip-sync detector closest to v1's focus; no licence stated). The AI-Face fairness checkpoints (PG-FDD, DAW-FDD, DAG-FDD) sit in a login-walled SharePoint folder and saw Celeb-DF v2; PG-FDD's own repo ships no trained weights. The MAVOS-DD baselines were fine-tuned on MAVOS-DD itself. Community classifiers on Hugging Face (wav2vec2 and ViT fine-tunes with undisclosed training data) are left out.
